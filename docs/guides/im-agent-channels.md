# 消息渠道使用教程：把飞书 / 钉钉接入 AnQiCMS

本文面向站点管理员，说明如何在 AnQiCMS 后台配置企业 IM 渠道，实现两件事：

1. 网站产生留言、订单等事件时，主动推送到指定的飞书 / 钉钉群或已绑定管理员的私聊；
2. 管理员在私聊或获得授权的群里，通过对话管理网站。

> 适用版本：2026-11-09 授权收敛后的实现。渠道聊天与 AI 助手、MCP 共用同一套授权（站点意图曝光 + 接口开放范围），后台不再有第二套渠道授权。
> 尚未使用真实飞书、钉钉租户完成验收，平台侧权限项名称、字段获取入口与主动发送能力以平台当前文档为准。未验证项集中列在第 11 节。

## 0. 最短路径

如果只想先跑通，按下面五步走，细节见后文：

1. 在平台创建企业自建应用，开启机器人能力，使用长连接 / Stream 模式接收消息；
2. 在 AnQiCMS「插件 → 消息渠道 → 渠道连接」新建渠道，填写应用 ID、应用密钥（组织标识可留空，由系统自动获取），启用连接；
3. 先在「AI 智能体」里建好接待智能体，回来把渠道的「聊天管理」打开并选中它；
4. 在「身份绑定」生成一次性 Token，在平台私聊里发给机器人完成绑定；
5. 在「会话目标」添加群并把「批准通知」置为「是」，「通知规则」里新建规则并选中目标。

完成后，私聊机器人即可对话；群聊默认只收通知，需要在目标上额外开启「允许群管理」。

> 前提：渠道能执行哪些操作，完全由站点在「设置 → AI 统一配置 → MCP 开放接口」里的配置决定——「允许使用的工具」决定意图曝光，「接口开放范围」限制 `api_invoke` 能到达的端点。渠道内部没有能力开关，见 2.2。

## 1. 前置条件

### 1.1 平台侧

两个平台都使用**长连接**：由 AnQiCMS 主动连接平台，不需要公网回调地址，也不需要开放入站端口。

飞书：

- 创建企业自建应用，开启机器人能力；
- 订阅「接收消息」事件（`im.message.receive_v1`）；
- 为消息添加表情回复：开通 `im:message.reactions:write_only`（以及 `im:message`），用于「收到即回执」，见 7.5；
- 发布应用版本并安装到企业，把机器人加入目标群；
- 记录 App ID、App Secret（组织标识无需手动查找，系统会自动获取）。

钉钉：

- 在开发者后台创建企业内部应用，添加机器人；
- 消息接收模式选择 Stream 模式；
- 发布并安装到企业，把机器人加入目标群；
- 记录 AppKey、AppSecret（企业 `corp_id` 无需手动查找，系统会自动获取）。

> 平台后台的具体菜单名称会随版本变化，本文不锁定入口路径。需要在平台侧确认的只有三件事：应用凭据、机器人已启用、消息通过长连接 / Stream 送达。

### 1.2 平台标识

后台需要填写两类平台标识，来源不同，不能混用：

| 标识 | 飞书 | 钉钉 | 说明 |
|---|---|---|---|
| 应用 ID | App ID | AppKey | 入站事件会校验应用一致 |
| 组织标识 | `tenant_key` | `corp_id` | 入站事件会校验组织一致；留空自动获取 |
| 群目标标识 | `chat_id` | `openConversationId` | 通知与群管理都按它定位群 |
| 私聊用户标识 | `open_id` | 企业内 `staffId` | 绑定后自动生成私聊目标 |

> 组织标识**留空即可**，建连前会先调平台接口自动获取：飞书用 `tenant/v2/tenant/query` 读 `tenant_key`，钉钉用 `gettoken` 读 `corp_id`。飞书需要在应用权限里加上 `tenant:tenant:readonly` 并**重新发布版本**，否则接口拿不到值。
> 接口取不到时，改用该渠道的**首条入站消息**锚定企业，之后按锚定值严格校验；锚定值会写回渠道配置，连接按新配置重建。
> 校验始终是严格相等：锚定后事件里的组织不一致会被丢弃，日志写「事件来源组织与渠道配置不一致」；事件本身缺组织则写「事件来源组织不能为空」。
> 手工填写仍然支持，且优先级最高——已有手工值时不会被自动获取覆盖。

### 1.3 CMS 侧

- 当前管理员可以登录后台，并拥有新增的菜单权限「消息渠道」（`/plugin/channels`）；
- 已经创建至少一个 AI 智能体，作为渠道的接待智能体；
- 需要管理的功能已在站点「设置 → AI 统一配置 → MCP 开放接口」里开放：渠道与 AI 助手、MCP 共用同一份意图曝光与接口开放范围，聊天对象就是渠道配置的接待智能体。渠道不再有独立的授权配置。

## 2. 新建渠道

进入「插件 → 消息渠道」，默认在「渠道连接」标签页，点击「新建渠道」。

### 2.1 字段说明

| 字段 | 必填 | 说明 |
|---|---|---|
| 平台 | 是 | 飞书或钉钉，保存后不建议修改 |
| 渠道名称 | 是 | 仅后台展示用 |
| 应用 ID | 是 | 飞书 App ID，或钉钉 AppKey |
| 组织标识 | 否 | 飞书 `tenant_key`，或钉钉 `corp_id`。留空自动获取，见 1.2；手工填写可覆盖自动值 |
| 应用密钥 | 新建必填 | 保存后只显示掩码；编辑时保持原样提交即沿用库中真值 |
| 启用连接 | 是 | 为「是」时才建立长连接，**通知投递也要求渠道启用** |
| 聊天管理 | 是 | 开启后由接待智能体处理聊天；关闭则渠道只用于通知 |
| 接待智能体 | 开启聊天管理时必填 | 从已有 AI 智能体中选 |

保存成功后，如果连接没能在本次请求内重建，页面提示「已保存，连接将在稍后生效」，由后台扫描继续建立连接。

### 2.2 能力范围：与 AI 助手、MCP 同源

渠道没有自己的授权配置。一次操作能在渠道里执行，取决于下面三项，任一项不满足都会被拒绝：

1. **站点意图曝光**：站点在「设置 → AI 统一配置 → MCP 开放接口 → 允许使用的工具」里放行的意图；
2. **接口开放范围（`api_exposure`）**：`api_invoke` 调用具体端点时统一执行的闸门，与 MCP 完全同一条；
3. **身份与状态**：发送人已完成绑定、管理员账号有效、渠道 `enabled=1` 且 `chat_enabled=1`、执行主体与渠道接待智能体一致。

渠道不复制也不放宽这些判定；它只回答「谁在操作、这个渠道还能不能用、这条群消息能不能执行」。因此：

- 想放开某项能力，在站点曝光或接口开放范围里放开一次即可，不需要（也没有入口）在渠道里再配置；
- 历史遗留的渠道策略与审批数据（如有）不再参与任何判定，也不会被执行，无需手工清理；
- 群聊是唯一额外收窄的场景：群里只放行只读的接口元数据查询（`api` 的 `schema`），其余操作要求到私聊进行，见 5.3。

> 已知代价：「允许使用的工具」留空并不等于关闭——除 `DefaultOff` 的高危意图（如 `system_plugin` 的备份、迁移）外，其余意图都会开放，其中包括主机级 `shell_exec`、`fs_*` 与联网工具 `web`。要收窄必须显式填入清单，只保留需要的意图。如果站点曝光放行了这些主机级能力，绑定管理员也可以在私聊里触发；`api_invoke` 在接口开放范围允许时能到达的后台端点与 MCP 一致。要收窄就在曝光或接口开放范围里收窄，渠道不再叠加一层。

### 2.3 查看能力

在渠道行点击「查看能力」，打开的是只读诊断表，按意图列出：

- 名称与标题、风险等级、所属域、动作列表；
- 「站点开放」：该意图是否在站点曝光内（与执行判定同一口径）；
- 「群聊可用」：是否属于群安全清单（当前只有接口元数据查询）。

这里没有任何可编辑项，也不能在此处授权。显示「未开放」说明站点曝光没有放行，需要去「MCP 开放接口」里调整。

## 3. 连接状态、配置校验与试发

### 3.1 查看状态

渠道行点击「查看状态」，显示：

| 项目 | 含义 |
|---|---|
| 已连接 / 未连接 | **当前响应请求的这个进程**是否持有该渠道的运行中连接 |
| 租约到期 | 连接工作者持有的租约到期时间 |
| 待发投递 | 排队中的通知投递数量 |
| 失败投递 | 失败或结果未知的投递数量 |

> 多实例部署时，状态页只代表单个实例的视角。「未连接」不等于集群里都没有连上，判断全站故障要看日志与投递记录。

### 3.2 校验配置

点击「校验配置」只检查必填项与适配器能否构造，**不会连接平台**。因此结果提示是：

> 必填项已填写，但未连接平台验证（长连接建立成功才代表可用）

这不代表渠道可用。真实可用性只有两种证据：长连接建立成功，或一次真实试发成功。

### 3.3 试发

点击「试发」，选择一个已批准的目标，发送一条示例消息。结果分三类：

| 结果 | 含义 | 处理 |
|---|---|---|
| 示例消息已发送 | 平台接受了这次发送 | 成功 |
| 凭据或主动发送权限有误 | 永久失败，通常是密钥错误、机器人未启用主动发送或目标标识错误 | 检查平台配置 |
| 平台或网络暂时不可用 | 临时失败 | 稍后重试 |

试发会写入审计记录（动作 `channel.test`）。留空目标时等同于「只校验配置」，返回「未验证」。

## 4. 绑定管理员身份

绑定把「平台上的这个人」和「后台的某个管理员」关联起来。绑定之后，私聊可以管理网站，也会自动成为通知接收目标。

### 4.1 生成 Token

1. 进入「身份绑定」，点击「生成绑定 Token」；
2. 选择渠道；
3. 明文只显示一次，页面显示 1 小时倒计时；关闭弹窗或切换标签页后无法再次查看；
4. 立即复制。

> 为同一管理员、同一渠道重新生成 Token 会让之前未使用的 Token 立即失效。Token 明文不写日志、不写浏览器存储，数据库只保存摘要。

### 4.2 完成绑定

在平台的**应用私聊**里，把 Token 作为**整条消息**发给机器人：

- 只能私聊，群聊里的 Token 不会被处理；
- 消息必须只包含 Token 本身，前后加字会导致识别失败；
- 成功回复「绑定成功」；
- 失败回复是固定文案，例如「绑定令牌无效或已过期」「该平台身份已绑定，请先解绑后再试」「该管理员在当前渠道已有绑定，请先解绑后再试」；
- 10 分钟内最多尝试 5 次，超限回复「尝试过于频繁，请稍后再试」。

绑定成功会同时做三件事：

1. 建立平台身份到管理员的绑定；
2. 创建（或重新批准）该管理员的私聊目标，用于通知与聊天回复；
3. 如果这个平台身份此前绑定过（换绑复活），会增加会话代次，使旧会话、旧排队任务全部失效；全新绑定没有历史工作需要清理。

### 4.3 查看与解绑

- 默认只显示当前管理员自己的绑定；超级管理员可以切换「查看全部」；
- 解绑是立即生效的：排队中的入站任务取消，私聊目标收回；
- 管理员可以解绑自己；解绑他人需要超级管理员；
- 解绑后需要重新生成 Token 才能再次绑定，不能复用旧 Token。

管理员账号被停用期间，该身份在渠道里的操作会被拒绝；重新启用后按当前权限重新判定，但不会恢复已经取消的任务。

## 5. 会话目标

「会话目标」决定哪些群可以收通知、哪些群可以管理，以及私聊目标的来源。

### 5.1 群目标

选择渠道后点击「添加群目标」，填写：

| 字段 | 说明 |
|---|---|
| 平台群标识 | 飞书 `chat_id`，或钉钉 `openConversationId` |
| 批准通知 | 为「是」才允许向该群投递通知 |
| 允许群管理 | 为「是」才允许在该群执行管理操作 |

同一渠道下，同一平台群标识只能登记一次。

### 5.2 私聊目标

私聊目标不在这里新建，由绑定流程自动产生并标记为已批准。这是刻意的：私聊目标必须对应一条有效绑定，手工造一个私聊目标没有可执行的身份。

### 5.3 群管理的生效条件

群里的消息要真正进入执行链路，必须同时满足：

1. 该群已登记为目标；
2. 目标的「批准通知」为「是」；
3. 目标的「允许群管理」为「是」；
4. 发送人本人已完成绑定；
5. 消息明确 @ 了机器人；
6. 请求的能力属于「群安全清单」。

说明：

- 群里没有 @ 机器人的消息会被直接丢弃，不落库、不回复；
- 第 6 条是首版最严格的限制：群安全清单目前只放行 `api` 的 `schema` 动作（只读接口元数据）。其它能力即使在私聊可用，群里也会回复「该操作请在私聊中进行」；
- 群目标未批准或未开启管理时，管理请求不会执行；出于不向未授权会话确认机器人存在的考虑，这类请求通常不回复，只在「运行记录 → 入站任务」里留原因；
- 群聊不放行写操作，也没有二次确认环节；需要管理网站时回到私聊完成。

## 6. 通知规则与模板

### 6.1 事件类型

首版支持四类事件：

| 事件 | 触发时机 |
|---|---|
| 新留言（`guestbook.created`） | 访客提交留言 |
| 新订单（`order.created`） | 订单创建 |
| 订单支付（`order.paid`） | 订单支付成功 |
| 智能体执行失败（`agent.failed`） | 渠道聊天中工具调用失败 |

`agent.failed` 是从运行记录派生的近似事件：只取最近 10 分钟内、来自有效绑定的失败审计，不扫描「权限拒绝」。管理员在后台的试发失败不会触发它，避免往群里发无关噪音。事件载荷只含标识与动作名，不含参数正文、错误原文或用户消息。

### 6.2 新建规则

在「通知规则」标签页的规则表格点击「新建规则」：

| 字段 | 说明 |
|---|---|
| 规则名称 | 后台展示用 |
| 事件类型 | 从上面四种中选一个 |
| 接收目标 | 可多选，包含群目标和绑定产生的私聊目标 |
| 通知模板 | 可为空；为空时使用该事件的默认模板 |
| 启用 | 为「是」才会投递 |

投递成立需要同时满足：

1. 规则启用；
2. 事件类型匹配；
3. 目标存在且「批准通知」为「是」；
4. 目标所属渠道「启用连接」为「是」。

修改规则不会补发历史事件。手动重试只针对已经产生且失败或结果未知的投递记录。

### 6.3 模板

模板是独立的聊天文案，**不复用邮件通知模板的 HTML**。默认模板只使用公共字段：

```text
[{{ site_name }}] {{ event_label }}
编号：{{ business_id }}
时间：{{ occurred_at }}
```

公共变量（群聊与私聊都可用）：

| 变量 | 说明 |
|---|---|
| `site_name` | 站点名称 |
| `site_url` | 站点地址 |
| `event_type` | 事件类型标识 |
| `event_label` | 事件中文名 |
| `business_id` | 业务编号 |
| `occurred_at` | 预格式化时间，`2006-01-02 15:04:05` |
| `occurred_time` | 时间对象，仅用于 `date` / `time` 过滤器 |
| `amount` | 金额（元） |
| `status` | 状态 |
| `order_type` | 订单类型 |

私聊额外变量（群聊**不会**注入）：

| 变量 | 说明 |
|---|---|
| `guestbook.user_name` / `guestbook.contact` / `guestbook.content` | 留言人、联系方式、留言内容 |
| `order.buyer_name` / `order.buyer_phone` / `order.buyer_email` / `order.buyer_address` | 买家信息 |
| `agent.action` / `agent.error` | 失败的动作与错误摘要 |

模板使用受限的 Pongo2 语法：只允许白名单内的标签与过滤器，模板没有文件加载能力，`include`、`extends` 之类无法读取服务器文件。语法错误由服务端在保存时提示。

群聊模板只能拿到公共变量，这是硬约束：平台覆盖也不能绕过，群里不会出现联系方式、地址或留言原文。

### 6.4 平台覆盖

「平台覆盖 JSON」用于给不同平台准备不同文案，格式是「平台名 → 标题 / 正文」：

```json
{
  "feishu": {"subject": "飞书标题", "content": "飞书正文：{{ event_label }}"},
  "dingtalk": {"subject": "钉钉标题", "content": "钉钉正文：{{ event_label }}"}
}
```

留空的字段沿用通用模板。平台名只认 `feishu` 与 `dingtalk`，必须是 JSON 对象。

### 6.5 预览

模板行点击「预览」，选择目标类型（群 / 私聊）并填写示例载荷，可以看到实际渲染结果。预览与真实发送使用同一套字段约束，因此「预览里没有的字段」不要指望发送时出现。

### 6.6 投递与重试

每条投递独立推进状态：

| 状态 | 含义 |
|---|---|
| 待处理 / 发送中 | 排队或正在发送 |
| 已发送 | 平台接受 |
| 待重试 | 临时失败，等待下一次尝试 |
| 失败 | 永久失败或次数用尽 |
| 结果未知 | 请求已发出但无法确认平台是否收到 |
| 已取消 | 发送前复核发现规则停用、目标未批准、渠道停用、绑定撤销或管理员停用 |

- 最多尝试 6 次；前 5 次失败后的退避为 10 秒、30 秒、2 分钟、10 分钟、30 分钟；
- 只有可明确判定的临时失败才会自动重试；凭据、权限、目标失效属于永久失败；
- 结果未知的记录允许人工重试，但可能造成重复通知，页面的重试确认只保证「重新投递」，不保证去重；
- 单个目标失败不影响其它目标。

## 7. 在私聊里管理网站

### 7.1 执行权限

私聊消息由渠道的接待智能体处理。一次调用能否执行，取决于下面各项，全部满足才执行：

1. 站点在意图层开放了该意图（「允许使用的工具」，判定与 MCP 同一套 `IntentAllowed`；该字段留空即开放除默认关闭外的全部意图，见 2.2）；
2. `api_invoke` 还要通过「接口开放范围」（`api_exposure`）——开放模式、命名空间黑白名单与禁止端点，与 MCP 完全同一条；
3. 渠道 `enabled=1` 且 `chat_enabled=1`，执行主体与渠道配置的接待智能体一致；
4. 发送人的绑定仍有效（未撤销、未换绑、属于本渠道），且管理员账号处于启用状态。

渠道不再校验后台菜单权限，也没有第二套授权：操作能不能做，只由站点曝光与接口开放范围决定。

### 7.2 渠道专属限制

渠道只保留两类专属约束，都不是第二套授权：

- **群聊安全清单**：群里只放行 `api` 的 `schema`（只读接口元数据），其它操作回复「该操作请在私聊中进行」；
- **生命周期与身份**：渠道停用、仅通知（`chat_enabled=0`）、接待智能体不一致、绑定撤销、管理员停用，任一不满足都拒绝。

主机级能力（`shell_exec`、`fs_*`、`web_*`）不再被渠道单独关闭：它们是否可用只看站点曝光。这是统一授权的直接结果，介意的话在站点曝光里不要放行。

### 7.3 回复格式

模型回复使用 Markdown，由平台适配器按各自格式发送：

| 平台 | 发送结构 | 说明 |
|---|---|---|
| 飞书 | `post` 消息 + `md` 标签 | 富文本内容为 `{"zh_cn":{"content":[[{"tag":"md","text":"..."}]]}}`，标题、列表、代码块等由飞书渲染 |
| 钉钉 | `sampleMarkdown` | `msgParam` 为 `{"title":"...","text":"..."}`；标题取正文首个非空行（跳过代码围栏内的整段代码），去掉行首 Markdown 标记并截断 |

模型被要求只使用两平台公共子集：标题、列表、粗体、行内代码、代码块与链接；不使用 HTML、图片与表格（钉钉不渲染 GFM 表格）。

只有**模型回复**走 Markdown。绑定回执、错误提示、群限制提示、权限拒绝文案与通知投递仍是纯文本，不改变渲染格式。

长回复按平台上限分段续发：飞书 3500 rune、钉钉 1800 rune（保守值，未用真实租户校准）。切点优先选空行、其次换行；如果切点落在代码围栏内，该段会自动补上闭合围栏，并在下一段重开同语言围栏，保证每段都是合法 Markdown。

### 7.4 入站消息格式

首版只处理文本。语音、图片、文件、卡片回调不会进入模型；超长文本会截断后入站。入站去重按平台事件标识做，平台重投不会重复执行。

### 7.5 收到即回执

模型与工具执行通常需要几秒。消息落库后，机器人会立刻在原消息上贴一个表情，表示「已收到，正在处理」，不必等正式答复：

| 平台 | 回执形态 | 说明 |
|---|---|---|
| 飞书 | 消息表情 `OnIt` | 需要应用开通 `im:message.reactions:write_only`；不会产生额外消息气泡 |
| 钉钉 | 自定义文字表情「收到」 | 通过机器人表情回复接口贴在原消息上，同样不产生额外气泡 |

回执固定开启，没有后台开关。它只发生在**真正会被执行**的消息上：发送人已绑定、聊天管理已开启、渠道已配置接待智能体、群目标已批准且开启管理，且消息是文本。未绑定来源与仅通知渠道不会收到任何回执，避免向陌生人确认机器人存在。

回执失败只记日志，不影响消息本身的处理与正式答复；平台重投也不会重复回执。首版不会在答复后撤回表情——表情本身只是「收到」，不是「处理完成」。

## 8. 运行记录

「运行记录」标签页按类型查看三类记录：

| 类型 | 内容 | 状态 |
|---|---|---|
| 投递 | 通知发送任务 | `pending` / `sending` / `sent` / `retry` / `failed` / `unknown` / `cancelled` |
| 入站任务 | 平台消息的排队与处理 | `pending` / `processing` / `done` / `failed` / `cancelled` |
| 审计 | 执行与试发结果 | `ok` / `failed` / `denied` |

入站任务常见的 `done` 原因包括：聊天管理关闭、来源未绑定、渠道已删除、卡片动作（首版不处理）。失败原因写在「原因」列，只保留脱敏后的单行摘要。

投递记录只有 `failed` 或 `unknown` 才显示「重试」按钮。

## 9. 常见问题排查

### 9.1 管理操作被拒绝时的四步排查

1. **站点意图是否曝光**：在「设置 → AI 统一配置 → MCP 开放接口 → 允许使用的工具」确认该意图已放行；也可在渠道「查看能力」里看「站点开放」列。未曝光时模型根本看不到该工具，伪造调用名会回复「该工具未在渠道开放」。
2. **接口开放范围是否允许该端点**：`api_invoke` 受「接口开放范围」约束（只读 / 读+写 / 全部，以及命名空间黑白名单、禁止端点）。接口元数据查询（`api` 的 `schema`）本身不触达业务端点，不受这一步限制；真正调用端点会在这里被拦。
3. **渠道与接待智能体是否一致**：渠道 `enabled=1` 且 `chat_enabled=1`，实际执行的智能体就是渠道配置的接待智能体。渠道停用不会建连、也收不到消息；仅通知（`chat_enabled=0`）的入站消息静默丢弃，不发回执，只在「运行记录 → 入站任务」留下 `done` 原因「聊天管理未开启」。智能体不一致会回复「执行智能体与渠道不一致」。
4. **绑定与管理员是否有效**：发送人绑定未撤销、未换绑且属于本渠道，管理员账号启用。绑定类拒绝通常不回复，只在「运行记录 → 入站任务」留原因。

群聊额外检查两点：群目标已登记且「批准通知」「允许群管理」均为「是」；请求是否属于群安全清单（只有 `api` 的 `schema`）。

| 现象 | 先检查什么 |
|---|---|
| 保存后一直「未连接」 | 渠道是否启用；应用 ID / 密钥是否正确；服务器能否出站访问平台；日志里是否有建连失败。多实例时确认看的是持有连接的实例 |
| 「校验配置」通过，但收不到消息 | 这是预期行为：校验不连接平台。看「查看状态」是否已连接，再做一次试发 |
| 私聊机器人没有反应 | 是否完成绑定；聊天管理是否开启；是否选择了接待智能体；该意图是否在站点曝光内、接口开放范围是否允许该端点；管理员是否被停用；「运行记录 → 入站任务」的原因列。按 9.1 四步排查 |
| 群里 @ 了也没反应 | 是否真的 @ 了机器人；群目标是否存在；「批准通知」「允许群管理」是否都为「是」；发送人是否已绑定；请求能力是否属于群安全清单（首版只有 `api` 的 `schema`） |
| 群里回复「该操作请在私聊中进行」 | 命中了群安全清单限制，改到私聊操作 |
| 通知没有发到群里 | 规则是否启用；事件类型是否匹配；目标「批准通知」是否为「是」；渠道是否启用；「运行记录 → 投递」的状态与原因 |
| 试发提示「凭据或主动发送权限有误」 | 应用密钥、机器人主动发送权限、目标标识（`chat_id` / `openConversationId`） |
| 飞书事件全部丢失 | 组织标识是否已锚定且等于事件里的 `tenant_key`。日志文案：「事件来源组织不能为空」或「事件来源组织与渠道配置不一致」 |
| 钉钉事件全部丢失 | 组织标识是否已锚定且等于企业 `corp_id`；消息接收模式是否为 Stream |
| 日志出现「自动获取组织标识失败」 | 这是预期内的回退：接口没取到值，改用首条入站消息锚定。若既没日志锚定也收不到消息，检查飞书是否授予 `tenant:tenant:readonly` 并重新发布版本、服务器能否出站访问平台 |
| 消息能回复，但没有「收到」表情 | 飞书是否开通 `im:message.reactions:write_only` 并重新发布版本；钉钉是否允许机器人表情回复；日志里是否有「收到回执未发出」。回执失败不影响正常答复 |
| 解绑后立刻不能用了 | 这是设计行为：排队任务与私聊目标授权同时失效 |
| 管理员停用后渠道拒绝操作 | 每次执行都会重新读取管理员状态；站点曝光与接口开放范围在保存设置后生效 |

## 10. 安全与数据边界

- 绑定 Token 明文只在生成响应里出现一次，数据库只保存摘要；不写日志、不写浏览器存储、不放进 URL；
- 绑定消息不会把 Token 正文写入入站任务表；日志对疑似 Token 做脱敏；
- 未绑定的来源不进入模型、不回复：任何回执都等于向陌生人确认机器人存在；
- 消息正文入库前会脱敏疑似密钥与 Token，并截断超长内容；日志不记正文；
- 群聊只使用公共模板字段，平台覆盖不能绕过；群里不投递联系方式、地址、留言原文；
- 敏感结果不进入群：群安全清单只放行只读接口元数据；
- 每次工具调用前都重新复核绑定、管理员状态、渠道启用状态与接待智能体，任一项变化立即生效；
- 渠道配置接口不返回密钥明文与内部摘要，只返回掩码与白名单字段。

## 11. 当前边界与未验证项

首版实现完成并通过了离线测试，但没有真实平台租户，以下内容**尚未验收**，上线前需要按平台实际环境逐项确认：

- 飞书、钉钉的真实建连、收发消息、主动群发与私聊发送；
- 平台权限项的确切名称与最小授权集合；
- `tenant_key` / `corp_id` 自动获取接口在真实租户上的返回结构（已按官方接口实现，未用真实租户验收）、`chat_id` / `openConversationId` 在平台后台的实际获取入口；
- Markdown 在真实会话里的实际渲染效果（标题、列表、代码块、链接），以及长回复分段后的围栏续接；
- 单条消息的分段上限（飞书 3500、钉钉 1800 rune 的保守值，未用真实租户校准）；
- 断线重连的探活阈值（未在真实租户校准）；
- 多实例部署下的连接租约与消费行为（只做了逻辑与单实例验证）。

首版明确不支持：

- 按钮 / 卡片交互（飞书 ws SDK 无法接收卡片回调，钉钉侧也没有对应的发送能力）；
- 语音、图片、文件与文档命令；
- 通知摘要、定时汇总、按条件分流的复杂路由；
- 群聊里的通用管理能力（只放行只读接口元数据）。

如果这些边界影响使用，请先在测试租户完成第 11 节的真实环境验收，再决定是否扩大群安全清单或补充卡片交互。
